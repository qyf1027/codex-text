# 排期计算说明

- 日期以本地 `YYYY-MM-DD` 保存。工作日是周一至周五；开始日计作第 1 天。周末实际发生的事项照实记录，计划日期按工作日推进。
- 工作区中的任务、成果、GA 和项目有稳定 UUID。依赖可以从任务开始、任务完成或具体成果指向任务开始/成果；环路在保存前拒绝。成果引用可绑定已接受的版本，更新版本不会自动改写旧引用。
- 标准预测先按依赖拓扑传播最早开始，再分别计算任务完成和成果交付；成果的标准/最早偏移独立。实际开始、完成、交付日期保留事实，预测只更新尚未完成部分。缺失、失效或未交付的依赖单独形成风险。
- GA 由指定任务和成果的最晚完成日期决定。目标日期与硬截止分别比较；硬截止不满足的方案不可采纳。历史基准、标准预测、已采纳版本和实际记录单独存储。
- 压缩候选只改变尚可调整的任务工期和成果偏移，遵守各自最短值、依赖、资源和 GA 限制。候选只供用户预览；确认后原子保存为计划版本。
- 独占资源只按预约的工作日占用。固定日期预约和相对任务开始的预约都参与全局冲突检测。错峰比较不同顺序及其对各项目 GA 的影响；已有实际占用不可被候选移动。未确认外部资源条件先模拟，用户确认后再完整校验。
- 风险事件保存首次触发、最近评估和处理状态；重复重算不重复创建同一活动事件，复发会产生新事件。来源项目被删后，跨项目引用保持为缺失风险以便修复。

主要实现位于 `web/src/domain/forecast.ts`、`optimization.ts`、`resource-alternatives.ts`、`plan.ts`、`risk.ts`。具体边界以 `web/src/domain/*.test.ts` 为准。
