操作手册 / Visual Field Guide

从一个项目，
走通一条 IPD 时间线。

用真实界面截图，带你完成“建项目 → 写任务与成果 → 定 GA → 连依赖 → 看风险 → 采纳排期 → 备份”。第一次使用，先按第 3 节跟着做。

适用：IPD Smart Tracker Web App V1单人本地使用阅读约 12 分钟
01 / 页面地图

先认清 5 个页面

顶部标签负责切换工作；右上角的“切换项目”决定你正在编辑哪个项目。顶部的项目名称、启动日、优先级和说明可直接修改。

01总览

设置 GA、看标准预测、排期候选和风险历史。

02任务与成果

建立阶段、任务、成果；登记实际开始、交付、完成。

03跨项目依赖

把一个项目的成果作为另一个项目的前置条件。

04关键资源

登记独占设备预约，比较冲突处理顺序。

05数据管理

建项目、导入导出、查看计划与变更记录。

记住一件事：页面上的“已保存到此浏览器”表示自动保存完成。它只属于当前浏览器；换设备请使用完整工作区备份。
02 / 第一次操作

10 分钟走通一个最小例子

用“产品 A”作上游、“产品 B”作下游。下面的流程会循环点亮每一步；它是说明动画，不会修改你的真实数据。

建项目产品 A / B
→
写成果需求规格书
→
连依赖A → B
→
看排期GA / 风险
打开 数据管理，在“新项目名称”填写“产品 A”，点“新建”。
打开 任务与成果，新增“需求分析”，在“所属任务”选择它，新增必需成果“需求规格书”。
回到 总览，新增“TR1 评审”，设目标日期，完成判据选择“成果：需求规格书”。
再建“产品 B”，新增任务“样机测试”。
在 跨项目依赖 中，前置成果选“产品 A / 需求规格书”，目标选“产品 B / 样机测试”，点“建立依赖”。
回到 总览 查看预测和风险。给产品 A 的成果登记实际交付后，再看产品 B 如何变化。
第一次看到风险是正常的：前置成果尚未交付时，下游即使有预计日期，系统仍会提示“依赖未满足”。预计不等于已经发生。
03 / 项目骨架

项目、阶段和优先级怎么填

项目是最外层容器，阶段用于分组任务和 GA。先把结构建出来，再细化工期。新项目默认有一个 TR1 阶段；你可在“任务与成果”新增、重排或删除阶段。

创建：数据管理 → 新项目名称 → 新建；右上角切换项目。
描述：在页面顶部编辑名称、项目启动日期、优先级、状态和说明。
阶段：任务与成果 → 新增阶段；给任务指定阶段，再用“上移阶段 / 下移阶段”调整顺序。
归档与删除：归档保留项目数据和跨项目关系；删除会移除项目内容。其他项目对它的引用会保留为“来源缺失”，方便你修复，而不是自动视为已满足。
04 / 真正推进工作

任务是工作，成果是可交付的证据

阶段例如 TR1
→
任务例如需求分析
→
成果例如需求规格书 V1

每个任务有标准工期和最短工期。最短不能大于标准。成果有独立的标准交付偏移和最早交付偏移，不会简单随任务工期同比例压缩。

状态 / 字段何时使用要点
未开始任务还没实际启动系统按依赖和工作日预测。
进行中已经实际启动填写实际开始和预计剩余工作日；真实日期不会被预测覆盖。
已完成工作真实结束确认实际完成日期。必需成果须先交付；未交付普通成果须取消或转移。
成果已交付交付了一个具体版本先填实际交付日期，再改状态。版本记录会保留。
成果失效此前交付不再可用填写失效原因，检查直接和间接下游影响。
完成任务时的提示：必需成果未交付，系统拒绝确认；普通成果未交付，你可以取消、转移到其他任务，或暂不结束任务。取消不会自动解除依赖。
05 / 里程碑

GA 是要达到的关口，不只是一个日期

在“总览”顶部添加 GA：填名称、目标日期、所属阶段、截止类型和完成判据。完成判据可以是任务或成果；不设判据时需手动确认，页面会提示无法自动预测。

普通目标：晚于目标会出现 GA 延期风险，但仍可查看候选。
硬截止：候选若违反硬截止，会标记不可行，不能当作达成计划采纳。
实际达成：GA 真正达到时填写“实际达成日期”，与预测分开记录。

GA 行同时显示原始目标、原始预计、标准预计、已采纳版预计和实际达成，便于追溯“最初想怎样、现在预计怎样、最终发生什么”。

06 / 跨项目协同

让 A 的成果真正推动 B 的时间线

“跨项目依赖”的前置对象是成果，后续对象可以是任务开始或另一个成果交付。系统用稳定 ID 连接，改名不会断开关系；形成环路时会拒绝保存。

产品 A需求规格书交付
→
下一工作日依赖最早可开始
→
产品 B样机测试开始
在“前置成果”选择 A 的成果。
“后续对象”选任务开始或成果交付，再选 B 的目标。
点“建立依赖”；若 A 的交付变化，到 B 的总览查看预测与风险。
如果 A 的成果版本失效，在“成果变更影响处理”逐项选择不受影响、接受风险或需要返工。
版本不会偷偷切换：下游接受过 V1 时，A 交付 V2 并不表示下游自动接受 V2。需要在依赖页人工点击“接纳当前成果版本”。
07 / 设备冲突

只预约真正占用设备的那几天

“关键资源”适合测试设备、试验台等独占对象。先建资源，再选任务、预约方式和占用工作日数。一个 8 天任务若只占设备 2 天，预约填 2 天即可。

预约方式含义例子
锁定日期设备从指定日期开始占用11 月 2 日起，占 2 个工作日。
相对任务开始随任务预计开始日期移动任务开始后第 3 个工作日，占 2 天。

发生冲突时，点击“比较两种执行顺序”，对照各项目 GA 变化及硬截止结果，再决定是否“确认整体采纳”。第三方资源尚未确认时，只能先在“条件性补救模拟”中试算；确认资源和日期后再次校验。

08 / 决策而不是猜测

风险、候选、采纳是三件不同的事

标准预测

按当前任务、成果、依赖与资源计算；不因为候选好看就改掉。

未采纳候选

系统尝试压缩或错峰；显示约束和各 GA 影响，尚未写入正式计划。

已采纳版本

用户确认后形成版本。原始基准、风险历史和实际记录保留。

在总览找到对应 GA，点击“生成候选”。
阅读“标准预计 → 候选预计”、可行性、原因及其他 GA 影响。
可行且符合你的业务判断时点“确认采纳为新版计划”；否则“放弃候选”。
在“风险历史”可记录接受风险的意见或已落实的缓解措施。接受风险不等于风险消失。
不可达要如实处理：如果所有已知约束都无法满足硬截止，系统不能把违规方案写成“可行”。外部条件变化需先取得确认，再输入并重算。
09 / 数据安全

备份是你最重要的操作习惯

应用会自动把数据保存在当前浏览器。清理浏览器数据、使用无痕窗口或换设备前，请进入“数据管理”导出完整工作区 JSON。

备份：数据管理 → 导出完整工作区。保存下载的 ipd-workspace.json。
恢复：数据管理 → 导入完整工作区 → 选择 JSON → 查看待导入项目数 → 确认替换。
分享单项目：选择该项目 → 导出当前项目；接收方用“导入为新项目”。跨项目联合方案和完整历史应使用完整工作区备份。
旧版数据：用“导入旧版项目 JSON”转换原版项目 JSON；旧文件没有的成果、版本不会凭空生成。
恢复会替换当前工作区：先导出一份现有备份。损坏或不支持的 JSON 会被拒绝，现有数据不会因此覆盖。
10 / 计算口径

几个容易误会的规则

规则你会看到的结果
开始日算第 1 工作日周一开始、标准 3 工作日，预计周三结束。
前置成果交付后再开始周五交付，下游最早从下周一计划开始。
计划只用周一至周五真实开始/完成可以如实记录周末日期；计划不会把周末算工作日。
成果与任务各有最短值压缩任务不代表每个成果都同比例提前。
预测不覆盖事实实际开始、完成、交付、GA 达成由你记录，系统不会自动改写。
风险有历史接受风险或完成缓解后，首次发现和后续状态仍可回看。

目前未纳入国家法定节假日；候选是按当前已知约束生成的启发式建议，不保证数学上的全局最优。

11 / 常见问题

遇到问题先看这里

为什么任务明明有预计完成日，仍提示依赖未满足？

预计日只是计算结果。前置成果实际尚未交付，真实依赖就尚未满足。你可以继续如实登记下游实际进度，系统保留预警。

为什么“确认实际完成”按钮不能完成任务？

先检查必需成果是否交付、实际交付日期是否填写；再处理未交付普通成果：取消、转移，或暂不结束。错误提示会指出缺失项。

为什么资源候选不可采纳？

检查硬截止、其他预约、已有实际占用和依赖。候选卡片会说明不可行原因；可调整真实条件后重新比较。

改了成果名称，跨项目关系会丢吗？

不会。关系按内部稳定 ID 保存。若成果失效或删除，上下游仍会显示待处理关系或缺失风险。

没有 Gemini 密钥或断网还能用吗？

可以。本地排期、风险、保存和备份可离线使用。当前版本未连接 Gemini 在线建议，页面会明确提示。

为什么我在电脑浏览器打不开云端的 localhost:3000？

云端 localhost 属于远程工作环境，不是你的电脑。可下载独立 HTML；若浏览器限制本地文件，可在自己电脑的源代码目录运行 README 中的命令启动服务。

为什么换了浏览器数据不见了？

数据默认留在当前浏览器，不自动同步。请在旧浏览器导出完整工作区 JSON，在新浏览器导入恢复。
