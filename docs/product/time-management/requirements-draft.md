# 时间规划与专注 App：初步需求

状态：讨论稿，不是已批准的开发规格；本次仅整理需求和安装相关 Skill。

## 已确认

- 产品方向：时间规划与专注，以日历时间块、番茄钟、时间统计为核心。
- 客户端：Android 手机 App、Windows 电脑客户端。
- 跨设备同步同一账号的数据。
- 首版以联网使用为主，暂不实现离线编辑与离线同步。
- 云端先用托管服务，优先利用免费额度，超额后评估费用。

## 产品闭环与建议首版范围

以下为建议，仍需用户确认：

1. 收集待办：标题、备注、完成状态、预计投入时间。
2. 安排时间：将待办安排到日历时间块，支持创建、移动和调整起止时间。
   先做日／周视图；计划时间不等同于实际专注时间。
3. 专注执行：关联待办开始番茄钟，支持暂停、继续、结束；可调整专注与休息时长。
4. 回顾：按日／周查看实际专注时长、完成次数及任务分布，区分计划与实际。
5. 同步：手机和电脑上的任务、时间块和专注记录保持一致，并显示同步中、失败和重试状态。
6. 账号：先按一个人多设备使用设计；登录方式与是否开放他人注册待定。

## 必须在设计阶段明确的行为

- 一个账号是否只允许一个进行中的专注会话，及另一台设备如何接管。
  建议首版只允许一个，会话状态由云端协调，避免双重计时。
- 倒计时由开始时间、累计暂停时长和当前状态推导，不依赖页面持续运行；
  锁屏或切换应用后应能恢复正确显示。关闭后的提醒能力需单独验证。
- 短暂断网时提示连接状态；不可把未成功保存的数据显示为已同步。
  已开始的计时可按时间戳继续显示，但不能承诺离线修改已保存。
- 保存操作需要幂等、版本校验和明确的并发处理；不做离线并不消除两台在线设备同时编辑的冲突。
- 日期按用户时区展示，云端统一存储时间点，统计时明确跨午夜及跨时区的归属。
- 个人数据隔离；统计以唯一专注记录计算，重试不能导致重复累计。
- 删除、完成、取消时间块及删除专注记录如何影响统计。

## 建议暂缓

团队协作、AI 自动排程、外部日历双向同步、复杂习惯系统、付费订阅、
iOS/macOS 客户端、离线编辑、桌面小组件。提醒、重复计划和数据导出是否
进入首版仍需确认，不能视为已排除。

## 技术路线候选

| 路线 | 优点 | 代价 |
| --- | --- | --- |
| Expo / React Native（Android）+ React / Tauri（Windows） | 复用当前 React 技能和部分类型、业务逻辑；可逐端优化交互 | 两套界面；需 Rust/WebView 与桌面系统集成 |
| Flutter（Android + Windows） | UI 与业务逻辑复用较多 | 新增 Dart 体系；需核对桌面插件、通知与后台行为 |
| Kotlin（Android）+ WinUI（Windows） | 平台原生体验和系统集成 | 两套技术栈与较高维护成本 |

当前偏向第一条，尚未定案。安装相关 Skill 是备选能力准备，不代表技术选型已获确认。
云端采用托管服务。具体供应商、数据部署地区、可接受的超额费用和登录方式待补充。
Supabase/Postgres 是候选，需验证目标设备网络可达性、免费额度与配额限制，
不能把安装 Postgres 技能等同于已决定或开通 Supabase。

## 候选验收场景

- 手机创建待办并安排时间块，电脑无需手动刷新即可看到同一数据；
  同步延迟目标需在后续设计中确定并实测。
- 电脑调整时间块，手机显示一致的起止时间。
- 开始专注后锁屏，再打开仍显示正确剩余时间；结束后两端统计一致。
- 一次专注记录遇到重复提交或重连，不重复累计。
- 两端同时编辑同一条记录，产生可解释的结果，不静默丢失修改。
- 网络失败明确提示；恢复后可重试，不能伪装同步成功。
- 若未来开放多用户，账号 A 无法读取或修改账号 B 的数据。
