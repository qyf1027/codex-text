# IPD Smart Tracker V1 设计

## 依据与目标

以用户提供的 [PRD v1.0](../../requirements/IPD_Smart_Tracker_PRD_v1.0.md) 为完整需求和 AT-01～38 验收基线，以 `ipd-smart-tracker.zip` 为视觉及已有代码参考。PRD 已确认业务规则优先于此前的单项目设计。本文件说明工程方案，不缩减 PRD 的 P0。目标是离线可用的个人多项目 IPD 工作区，分别保存原始基准、当前标准预测、未采纳候选、历版已采纳计划、实际记录及风险历史。

应用独立放在 `/workspace/ipd-smart-tracker`，不混入 `codex-text`。实现前审计原 ZIP，复用可用界面和样本任务；旧代码中按名称关联、任务级串并行标签、直接压缩正式排期等逻辑须升级为 PRD 的成果依赖和候选采纳模型。

## 模块与数据流

工作区存储项目、可配置阶段、任务、成果及版本、GA、全局依赖、独占资源预约、计划版本、风险事件和审计记录。对象用稳定 UUID 关联；成果默认彼此独立，仅显式依赖传播。任务完成必须满足必需成果，并处理未交付普通成果。归档保留依赖；删除后保留可修复的缺失引用及风险。

`calendar` 用纯 `YYYY-MM-DD` 及周一至周五计算，开始日计第 1 工作日，成果交付后下一工作日才能计划启动下游。`validation` 和 `dependency-graph` 检查全工作区字段、引用及环，定位受影响子图。`forecast-engine` 融合实际、进行中剩余工期、成果和资源约束，以拓扑顺序产生可解释的标准预测；无法确定时返回原因，不造日期。实际和已交付成果不由算法改写。

`optimization-engine` 只对未来可调整部分生成有界数量的启发式候选；逐候选重新计算受影响图，检查任务最短工期、成果最早交付偏移、已发生事实、资源占用及硬截止。进行中任务只可调整剩余工作。`resource-engine` 只检查显式独占预约的工作日区间，同名负责人不构成冲突。不可达或资料不全的候选不标为可行，而展示条件性补救和待确认假设。跨项目候选在用户看过全部变动后整体采纳，事务生成新计划版本，不覆盖原基准或其他项目旧版计划。

`risk-engine` 保存风险首次快照、当前影响、处理意见和解除历史；接受风险不等于解除。成果失效会追踪直接及间接下游，但不撤销实际记录，也不自动让下游接受新版本。相同重算不重复生成活动风险。

## 保存、导入和兼容

用 IndexedDB 保存规范化的本地工作区。有效编辑自动保存并显示状态；多项目采纳以一个事务提交，失败则回滚并提示。提供完整工作区备份与单项目导出；导入先隔离校验 schema、日期、ID、关联、环、工期及资源，再选择新建导入或明确确认整库恢复。原 ZIP 的旧 JSON 格式只通过显式转换入口导入，无法推知的成果版本、历史或实际信息不伪造。若发现旧浏览器存储键，再做有证据的迁移。

## 界面与交互

保留原版首页的信息层级：项目名称和日期、GA 与进度、风险提示、阶段任务表；增加工作区切换、任务与成果详情、依赖修复、候选对比、跨项目资源风险及数据管理。P0 字段和动作须有可用入口。标准预测、候选、已采纳和实际明确区分；当前风险与历史分开展示。实际提前开工可记录并立刻提示风险。任务完成、成果失效、删除、覆盖导入和跨项目采纳均显示具体影响与错误反馈。桌面可高效编辑，窄屏仍能访问核心操作。

## 交付阶段与 AI

按 PRD M1～M5 依次完成：基础本地多项目、成果与依赖、预测与采纳、资源与补救、界面及回归。各阶段都应可运行、可构建、可测试；只有全部 P0 通过才宣称 V1 完成。Gemini 属于可选 P1，最后接入；离线规则提示属于 P0。AI 仅在用户主动确认发送最少必要的脱敏摘要后给出未经验证建议，不修改正式数据。密钥不写进仓库、导出文件或永久浏览器存储；无安全调用路径时保留离线能力并说明限制。

## 验证与已知界限

按 PRD AT-01～38 使用固定日期自动和界面验收，覆盖跨项目传播、成果独立性、环、资源冲突、硬截止、事务回滚、风险去重、完整备份往返及无网运行。用至少 10 项目、每项目 100 任务、每任务平均 3 成果检查性能和计算上限。每阶段执行类型检查、构建及对应测试，维护 `IMPLEMENTATION_STATUS.md`。最终交付 README、示例数据、算法说明和测试结果。启发式候选不保证数学全局最优；法定节假日、真实供应商承诺、跨设备同步及多人协作不在 V1 范围。
